# アクセシビリティ / ユーザビリティ チェックリスト

このプロジェクトのコンポーネント・生成LPに関係する項目だけを抜き出したチェックリスト。
根拠の詳細を確認したいときは、各項目に添えた参照先を読む。

このチェックリストは2箇所から使う:

- **コンポーネントを追加・変更するとき**(`SKILL.md`「既存ルールに無いUIが必要な場合」から参照): 下記「A. コンポーネント自体の構造チェック」を確認する。
- **LPのHTMLを生成したあと**(`SKILL.md`「作成後」から参照): 下記「A」に加えて「B. 生成したHTML全体のチェック」も確認する(実際のブランド色・実際のコンテンツで初めて判定できる項目のため)。

## A. コンポーネント自体の構造チェック

- [ ] **フォーカス表示**: `<a>`/`<button>` など操作可能な要素に `:focus-visible` を定義しているか(ブラウザ既定任せにしない)。基本形は `coding.md`「フォーカス表示(アクセシビリティ)」を参照。
  参照: `dads-markdown-20260909/components/button/index.md`(達成基準2.4.7/2.4.11)
- [ ] **ターゲットサイズ**: ボタン相当の要素は44×44 CSS px以上、それ以外のリンクでも最低24×24 CSS px以上のクリック領域があるか(小さい場合は上下左右の余白で確保)。
  参照: `dads-markdown-20260909/components/button/index.md`、`dads-markdown-20260909/foundations/link-text/index.md`
- [ ] **代替テキスト**: `<img>` の `alt` が、装飾目的(隣接テキストで内容が伝わる)なら `alt=""`、それ自体が意味を持つ画像(人物写真・図表など)なら具体的な内容を説明する `alt` になっているか。アイコンだけのボタン/リンクには `alt` または `aria-label` があるか。
  参照: `dads-markdown-20260909/components/image/index.md`、`dads-markdown-20260909/components/button/index.md`
- [ ] **見出し階層**: コンポーネント内の見出しレベル(`h1`/`h2`/`h3`)が `coding.md` の方針(h1はヒーロー1箇所、セクション見出しはh2、カード見出しはh3)と矛盾しないか。特に、そのコンポーネントを `p-section`(`c-section-head` がh2を出す)に入れて使う前提かどうかを明記しているか。
- [ ] **色だけに依存した表現をしていないか**: 重要度や状態(必須/エラー/成功など)を色の違いだけで伝えていないか(形状・アイコン・テキストを併用する)。
  参照: `dads-markdown-20260909/components/button/index.md`(達成基準1.4.1)、`dads-markdown-20260909/foundations/color/index.md`
- [ ] **リストのマークアップ**: `<ul>`/`<ol>` を使う場合、`role="list"` を付けているか(`reset.css` の `list-style: none` でSafari+VoiceOverがリストとして読み上げなくなるため)。
- [ ] **新規タブを開くリンク**: `target="_blank"` を使う要素に、新しいタブで開く旨の代替テキスト(視覚的に隠したテキストでよい)が付くようになっているか。
  参照: `dads-markdown-20260909/foundations/link-text/index.md`
- [ ] **無効化(disabled)の扱い**: ボタンを `disabled` にする設計になっていないか。どうしても無効化が必要な場合、その理由や有効化条件を近くにテキストで表示する仕組みになっているか。
  参照: `dads-markdown-20260909/components/button/index.md`

## B. 生成したHTML全体のチェック(実際のコンテンツ・ブランド色で確認)

- [ ] **コントラスト比**: 実際に使われている `brand.css` の色の組み合わせで、テキストは背景に対して4.5:1以上、非テキスト要素(ボーダー・アイコン・フォーカスリングなど)は3:1以上を満たしているか。特に `brand.css` に `TODO` が残っている色は、確定後に再確認する。
  参照: `dads-markdown-20260909/foundations/color/index.md`(達成基準1.4.3/1.4.11)
- [ ] **見出し階層(ページ全体)**: `<h1>` がヒーロー1箇所だけになっているか、セクションごとに `<h2>` が1つ、カード等に `<h3>` が正しく入れ子になっているか(重複・飛び級がないか)。
- [ ] **リンクテキストの目的の明確さ**: 「こちら」「詳しくはこちら」だけのリンクテキストになっていないか。同じ文言(「もっと見る」等)が複数箇所にある場合、それぞれの遷移先が区別できるか。
  参照: `dads-markdown-20260909/foundations/link-text/index.md`
- [ ] **画像のalt(実データ)**: ユーザーから提供された実画像に対して、`alt` が実際の内容(誰が写っているか、何の写真か)を反映しているか(コンポーネント側のテンプレートの `alt=""`/`alt={xxxAlt}` の使い分けが、実データでも適切か)。
- [ ] **キービジュアルの可読性**: `c-key-visual` など写真に重ねる見出しが、実際に使う写真でも十分読めるか(暗すぎる/明るすぎる写真で不安な場合は目視確認する)。
- [ ] **フォーム要素がある場合**: 入力欄に対応する `<label>` があるか、必須項目が色だけでなくテキスト(「※必須」等)でも示されているか(現状のコンポーネント一式にフォームは無いが、今後追加した場合に備えて確認する)。
